# S7 Robotics — 3D-симулятор BIOGLOW

Исходник 3D-симулятора, который открывается на странице **Our Robo Game** (`dist/game.html`). Перенесён из нашего проекта RoboEasy и оформлен в стиле сайта: тема BIOGLOW (`src/theme/theme.css`), шрифты DM Sans / Space Grotesk / Manrope, логотип S7.

**Собрать для сайта:**

```bash
cd simulator
npm install
npm run build   # готовые файлы попадают в ../dist/simulator
```

Собранная папка `dist/simulator/` лежит в репозитории: хостинг раздаёт `dist/` как есть и сам ничего не собирает. После правок в `simulator/` пересоберите и закоммитьте оба места.

**Пауза и Стоп** работают через SharedArrayBuffer, а для него нужны заголовки COOP/COEP. Статический хостинг их не ставит, поэтому их добавляет service worker `dist/coi-sw.js` (регистрирует `public/theme/isolation.js`). Его действие ограничено `game.html` и `simulator/`. В `npm run dev` заголовки ставит сам Vite.

# FLL BIOGLOW — симулятор игры роботов

Браузерный симулятор FIRST LEGO League Challenge **BIOGLOW (Founders Edition, сезон 2026/27)**:

- **Поле** 202 × 114 см с официальным матом, бортиками, двумя базами и зонами запуска.
- **15 миссий с физикой** (Rapier): рычаги, защёлки, храповики, пружины, сыпучие детали (семена, листья, кольцо-стяжка).
- **Подсчёт очков** по формулам официального Excel-калькулятора + Challenge Update 01 (Lucky Leaves). Максимум — 530.
- **Правила матча**: таймер 2:30, осмотр оборудования (одна зона запуска, ≤ 30,5 см), жетоны точности, прерывания вне базы,
  передача судье подобранных моделей, ограничение «без оборудования» 🚫🧱, док-станции M13–M15 (Шахта / Город / Ферма).
- **Конструктор робота** из деталей SPIKE Prime: хаб, большой/средний мотор, датчики цвета/расстояния/силы, балки, рамы, оси,
  штифты, колёса, шаровая опора, шестерни. Детали «прилипают» к отверстиям, анализ показывает, что не соединено с хабом.
- **Код на Python** (Pyodide в браузере): API **Pybricks** (`DriveBase`, `Motor`, `ColorSensor`…) и **SPIKE 3** (`motor_pair`, `runloop`…).

## Запуск

Нужен Node.js 18+.

```bash
npm install
npm run dev
```

Откройте http://localhost:5173. Готовая сборка: `npm run build`, затем `npm run preview` (http://localhost:4173).

> Сервер должен отдавать заголовки `Cross-Origin-Opener-Policy: same-origin` и `Cross-Origin-Embedder-Policy: require-corp`
> (в `vite.config.js` они уже прописаны) — без них кнопки «Стоп»/«Пауза» работают только через перезапуск симулятора.

## Как пользоваться

1. **🔧 Конструктор робота** — шаблон «Робот-база FLL» уже собран. Выберите деталь слева, наведите на отверстие — деталь
   прилипнет (жёлтая точка). `R` — другой вариант поворота, `T` — наклон, `C` — прицепить другим отверстием, `Esc` — закончить,
   `Del` — удалить, `G` — взять заново, `Ctrl+Z` — отменить. «📌 Авто-штифты» вставит штифты в соосные отверстия.
   Нажмите **«✔ Применить на поле»**.
   - **Настоящие отверстия**: у хаба, моторов и датчиков штифты и оси вставляются только в их настоящие отверстия
     (координаты взяты из моделей LDraw). Пока деталь в руке, свободные подходящие отверстия подсвечены зелёными кольцами.
     При установке балки или детали вплотную к соосным отверстиям штифты вставляются сами (галочка «Сразу закреплять
     штифтами при установке»). Шаблон «Робот SPIKE на настоящих отверстиях» собран целиком на настоящих отверстиях.
   - **Готовые роботы для новичков** (Шаблон… → выбрать → «Применить на поле», затем «Примеры…» → старт для этого робота):
     - **Cooper 2.0 — Platinum Pizzeria** (робот из их 530-очкового заезда BIOGLOW, модель BrickLink Studio 852730):
       большие моторы на колёсах 62,4 мм — B левое, F правое; две насадки спереди с шестерёнками 12z — D левая, C правая;
       датчик цвета A. Те же порты и диаметр колеса, что в их библиотеке `cooper`. Пример «Cooper 2.0: старт» (SPIKE 3).
     - **Робот с насадкой спереди** (по фото, только базовый набор): средние моторы на колёсах 56 мм — A левое, B правое;
       большой мотор насадки C с шестерёнкой 20z; шаровая опора спереди. Пример «Робот с насадкой спереди: старт» (Pybricks).
     Упрощено: рамы, панели и декоративные балки не перенесены — ходовая часть, моторы, порты и размеры колёс как у оригинала.
   - **🧩 Насадки**: соберите насадку прямо на роботе, выделите её детали (`Shift+клик`), впишите название и задание и
     нажмите «💾 Сохранить насадку» — она снимется с робота и сохранится отдельно. На поле все насадки лежат на полосах
     по краям стола (с подписью). Клик по насадке или кнопка в панели **🧩 Насадки** над полем надевает её на робота
     (детали встают туда же, где их собирали), повторный — снимает. В матче менять насадку можно только когда робот на базе.
     К каждой насадке можно привязать программу: при надевании она откроется в редакторе. «✎» в списке — вернуть насадку
     на робота в конструкторе, чтобы изменить.
   - **Поворот по осям**: `X` / `Y` / `Z` — повернуть выделенное (или ставимую деталь) на 90°, с `Shift` — на 15°.
     `Shift+клик` — выделить несколько деталей.
   - **`M` — Переместить** (как Move в Fusion 360): гизмо со стрелками (сдвиг по X/Y/Z), квадратами (в плоскости) и кольцами
     (поворот, переключение — `R`). Шаг 4 мм / 15°, с `Shift` — без шага. Справа можно ввести сдвиг в мм и поворот в градусах.
   - **`P` — Точка к точке** (Point to Point из Fusion 360): щёлкните точку на выделенной детали, потом точку на другой —
     выделенное переедет так, чтобы точки совпали. Точки прилипают к отверстиям и осям; с галочкой «выровнять оси» деталь ещё
     и повернётся, чтобы оси отверстий совпали.
2. **🏁 Поле и код** — пишите программу слева (код сохраняется сам; «＋» — отдельная программа для каждого задания,
   как слоты в приложении SPIKE; при следующем открытии откроется та же программа), запуск **▶ Запуск** (`Ctrl+Enter`). Кнопки **📝 Код** и **📊 Протокол**
   над полем прячут и показывают поле для кода и протокол очков (выбор запоминается). Когда код скрыт, кнопки
   «Запуск / Стоп / Прервать» переезжают на панель над полем. Робота можно перетащить мышью
   (колесо — поворот). Ручное управление: щёлкните по полю, `WASD` — езда, `R/F` — мотор C, `T/G` — мотор D.
3. Режим переключается над полем: **🏋 Тренировка** — без таймера и штрафов; **🏁 Матч 2:30** — сброс поля, осмотр,
   жетоны и таймер. Таймер запускается кнопкой **⏱ Старт 2:30** или сам с первым ▶ Запуск; **↻ Новый матч** — начать заново. **✋ Прервать** — вернуть робота на базу
   (вне базы −1 жетон). За северным бортиком стоит **судья** — большая LEGO-фигурка со смайликом в полосатой футболке JUDGE,
   рядом на стойке — 6 красных жетонов точности (как в правилах). За каждое прерывание вне базы судья поворачивается
   к стойке, берёт жетон, поднимает его и убирает в карман;
   «Новый матч» возвращает все 6. Между делом судья следит глазами за роботом.
   Когда 2:30 истекают, в правом верхнем углу поля появляется карточка **BIOGLOW**: все фолы (с временем), выполненные
   задания с баллами и ниже — сколько баллов набрал робот. **■ Стоп** — остановить на месте без штрафа.
4. Справа — протокол очков в реальном времени; там же выбор доков для M13–M15 и бонус M07 за соперника.
5. **🏠 На старт** — поставить робота в стартовую позицию базы, в которой он стоит (между выездами).

Робот по умолчанию: A — левое колесо (зеркальный, `Direction.COUNTERCLOCKWISE`), B — правое, C — рука с крюком,
E/F — датчики цвета. Колёса Ø56 мм, колея 136 мм.

## Движение 1:1 с реальным полем

Размеры поля — как в правилах: мат 2020 × 1143 мм, полосы хранения по 171 мм, внутренняя ширина стола 93″.
Один оборот колеса проезжает ровно π × диаметр (56 мм → 175,9 мм), моторы считают настоящие градусы, а `DriveBase`
пересчитывает миллиметры в градусы по `wheel_diameter` и `axle_track` — так же, как Pybricks на хабе. Поэтому программа,
которая выполняет миссию в симуляторе, задаёт роботу те же обороты, что и на реальном столе.

Проверено скриптом `node scripts/drive-check.mjs` (физика без браузера):

| Проверка | Ожидание | Симулятор |
|---|---|---|
| 10 оборотов вперёд, 200–1000 °/с | 1759,3 мм | 1756,3–1759,6 мм (≤ 0,2 %), увод курса ≤ 0,1° |
| 10 оборотов вперёд, 100 °/с | 1759,3 мм | 1755,4 мм (−0,2 %) |
| Разворот на месте: колёса по 720° в разные стороны, колея 136 мм | 296,5° | 296,2–296,6° |

Что для этого сделано (`src/sim/physics.js`): 8 внутренних итераций трения (раньше шины проскальзывали: −1,6…−3,6 %
пути и несколько градусов увода на метр) и компенсация «утопания» шины в мат на 0,09 мм.
Симулятор считает шину идеальной: ровно 56 мм. Реальная шина может отличаться на доли процента (износ, грязь, сжатие
под весом), плюс складки мата и люфт деталей. Проверьте свой робот тем же тестом: 10 оборотов колёс вперёд и замер
рулеткой. Если он проезжает 1759 ± 5 мм, выезды из симулятора переносятся на стол без правок.

пункт «⚡ Загрузить все выезды сразу» раскладывает их по вкладкам. Перед каждым выездом — **🏠 На старт**.

| Выезд | База | Миссии | Очки |
|---|---|---|---|
| 1 | левая | M01 дрон и LiDAR-карта | 30 |
| 2 | левая | M02 взрывающиеся семена | 30 |
| 3 | левая → правая | M03 камень, M05 корни, M09 платформа и фотоловушка, M08 лиана | 90 |

| 5 | правая | M12 трость, M07 мицелий, M06 муравей с листками | 80 |

С осмотром (20), жетонами (50) и домиками M10 (20) — 380 очков; проверено в матче, на таймере остаётся около 0:50.
Без насадок (только крюк) не выполняются M04, M13, M14, семя M09, стяжка M12 и бонус M03 — причины в справке.

| `src/sim/robotRuntime.js` | моторы (профили скорости, ограничение момента), DriveBase, датчики, гироскоп |
| `src/sim/python/` | модули Python API (Pybricks и SPIKE 3) |
| `src/render/` | Three.js: поле и меши; `ldraw.js` — настоящие модели деталей SPIKE Prime |
| `scripts/pack-ldraw.mjs` | собирает `public/ldraw/parts.bin` из `spike_prime_ldraw/` (`node scripts/pack-ldraw.mjs`) |
| `src/builder/builder.js` | конструктор робота |
| `src/ui/` | протокол, редактор кода, примеры, готовые выезды, справка |

Источники правил — папка `Manual/` (Robot Game Rulebook, Challenge Updates, официальный протокол и Excel-калькулятор).
Положения моделей сняты с мата и видео Field Setup; механизмы упрощены, но условия начисления очков те же, что в правилах.

Модели хаба, моторов, датчиков, колёс и рам SPIKE Prime — из библиотеки деталей [LDraw.org](https://www.ldraw.org)
(лицензии CC BY 2.0 и CC BY 4.0, см. `public/ldraw/CAreadme.txt`). Физика робота по-прежнему считается по простым
коллайдерам деталей; у моторов настоящий корпус длиннее коллайдера, модель выровнена по выходному валу.

## Просмотр BrickLink Studio и обмен файлами (дополнение)

В «Конструктор робота» → «Файл» выберите «Просмотр .io / .ldr / .mpd». Файл читается локально в браузере; никакой загрузки на сервер нет. Для типичных Studio `.io` извлекается `model.ldr` из ZIP и разворачиваются вложенные подмодели; позиции, матрицы и LDraw-цвета сохраняются. В окне просмотра мышью вращайте камеру, колесом меняйте масштаб, правой кнопкой сдвигайте камеру. Розовые проволочные рамки обозначают детали без геометрии; справа показан список идентификаторов и количества. Объекты и исходный LDraw-текст сохраняются при скачивании LDR. Ограничения: до 30 МБ распакованного описания и 10 000 деталей; нестандартные встроенные геометрии `.dat`, гибкие элементы и некоторые расширения Studio не поддерживаются. Используются только файлы `model.ldr`, не `model2.ldr`, поэтому цвета и пользовательские детали некоторых моделей могут отличаться.

Кнопка «LDraw .ldr» скачивает описание исходной импортированной модели, включая подмодели и ссылки на неизвестные детали. Это не экспорт изменений в конструкторе: просмотрщик пока не умеет редактировать детали. [Справка BrickLink Studio](https://studiohelp.bricklink.com/hc/en-us/articles/5406122578711-The-Studio-Welcome-Screen) указывает LDraw как поддерживаемый формат импорта; фактическое открытие полученного файла в Studio в этой проверке не подтверждено. `.io` не экспортируется.

«3D .glb» экспортирует визуальную геометрию просмотра, в том числе рамки отсутствующих деталей. Отдельная кнопка «Модель .glb» в конструкторе экспортирует геометрию текущей сборки. GLB удобен для просмотра в 3D-приложениях, но не хранит физику, соединения, порты и программу. Для дальнейшего редактирования робота используйте существующие «Сохранить .json» и «Открыть .json». Черновик конструктора сохраняется в локальном хранилище браузера отдельно от робота на поле; для переноса на другой компьютер сохраните JSON. Связи вычисляются по геометрии соединений после повторного открытия, а позиции, ориентации, цвета и назначенные порты хранятся в JSON.

### Что пока не реализовано

- Загрузка Studio пока открывает **отдельный просмотр**, а не конвертирует детали в редактируемый или физический робот. Автоматического сопоставления хаба, колёс, моторов, датчиков и точек соединения нет. Для симуляции используйте имеющиеся шаблоны конструктора, соедините совместимые части, назначьте порты и нажмите «Применить на поле».
- Каталог конструктора содержит существующее подмножество SPIKE Prime и общих Technic-деталей: балки, рамы, штифты, оси, шестерни, колёса, хаб, моторы и три типа датчиков. Полная библиотека SPIKE Prime и отдельные физические детали EV3 (EV3 Brick, EV3-моторы и датчики) не добавлены. Нельзя считать каталог полным.
- Библиотека геометрии просмотра — ограниченная выборка официального LDraw, а не полный каталог Studio. Для проверенной модели `wro 2026 robot.io` недоступны `39367pb01.dat` (2 экземпляра) и `bb1142c01.dat` (1); они обозначены рамками. Доступность для других моделей зависит от набора деталей.
